# Security remediation follow-up — 2026-09-15

## Result and boundaries

The confirmed local findings raised in the original assessment and this follow-up have been remediated in the working tree. The changes cover account protection, dependencies/document processing, Teams, tenant privacy, and workflow integrity. Implementation review, cross-review, and local workflow checks were completed. The original [assessment](security-assessment-2026-09-15.md) remains the record of its before-fix findings; this document supersedes its remaining-local-work and verification sections.

**Verification:** 255 application tests, 47 database/scanner guard tests, 40 disposable-PostgreSQL integration tests, and 42 actual HTTP checks passed. TypeScript, production build, and lint passed (20 existing lint warnings). The dependency audit reports **zero advisories**. These are bounded local results, not a claim that the application is free of vulnerabilities.

At assessment completion, all changes were **local and uncommitted**. Existing user changes were preserved. No push, deployment, production database access, real provider send, active external testing, or historical data deletion was performed. Provider configuration, production verification, and historical credential/retention questions remain open below.

The temporary application server was stopped and the disposable database container removed after verification; its data consisted only of synthetic test records.

## Scope and threat model

The stack is Next.js 15.5.25/React, NextAuth credentials and encrypted JWT sessions, Prisma 6.19.3/PostgreSQL, OpenAI, Resend, optional S3 avatars, and Microsoft Teams webhooks/Bot Framework. Global user identities are distinct from organization memberships. Public registration makes organization ownership an attacker-accessible role; it must not confer global account, platform, or cross-tenant authority.

The assessment considered anonymous clients, ordinary members, self-registered owners, removed/demoted users, malicious uploaded documents, stored content, supplied identifiers, and concurrent requests. Sensitive assets include passwords/reset authority, invitation consent, private recognition, individual strengths and performance reviews, AI conversations/context, integration credentials, and provider spending.

This pass expanded source review across dashboard, badges, leaderboard, challenges, mentorship, skill requests, reviews/cycles, notifications, settings, remaining recognition/matching AI paths, account linking, scheduler dispatch, and the current diff. It also inspected all 81 reachable Git commits and 673 distinct blobs for database credentials. API authorization remains the observed tenant boundary; production database row-level security, privileges, network controls and provider behavior were not established.

A fresh read-only pre-patch review identified additional Teams, digest, parser and retention issues. Independent cross-review covered the implementations. Source review, actual handler/helper tests, safe parser fixtures, real database concurrency and HTTP checks complement one another; none substitutes for production validation.

## Recommendations applied

- **Authentication abuse:** database-backed atomic counters work across application instances; recipient/source/global limits run before expensive hashing or email. HMAC keys avoid storing emails/IPs in counters; expired counters are removed in bounded batches. Forwarded IPs are ignored by default. A trusted single-IP header is optional and must be overwritten by the actual ingress. Requests and passwords are bounded. New users require verification; a migration preserves legacy sign-in without falsely marking old emails verified. See [authentication controls](security/authentication.md).
- **Session recovery and logs:** one server-initialized root session provider replaces nested providers that lost authentication state when navigating to account-link pages. Revoked sessions can reach the login page without a dashboard/login redirect loop. NextAuth metadata and raw provider/Prisma exception payloads were removed from inspected fixed-label logs; avatar failures return a generic error.
- **Dependencies:** compatible Next/PostCSS, Prisma/config/deepmerge and UUID updates were validated against real consumers; PDF parsing uses maintained `pdf-parse` 2.4.5. ESLint now uses flat configuration. Zero audit entries does not prove every dependency safe or cover future advisories. Primary sources: [UUID advisory](https://github.com/uuidjs/uuid/security/advisories/GHSA-w5hq-g745-h8pq), [deepmerge advisory](https://github.com/RebeccaStevens/deepmerge-ts/security/advisories/GHSA-ggr8-5vv4-36mx), [PostCSS advisory](https://github.com/postcss/postcss/security/advisories/GHSA-fxqj-rqcc-2cmp), [maintained PDF parser](https://github.com/mehmet-kozan/pdf-parse).
- **Internal/privacy hardening:** caller/context fingerprints prevent shared partnership caches from serving another caller's contextual analysis or old unbound entries. The currently unused exported ChatService now independently scopes ownership and active membership and persists atomically. Pagination is bounded before database offsets or list allocation. These were hardening recommendations; no reachable ChatService exploit was established.
- **Build/configuration:** standalone output and document tracing are enabled; postbuild removes generated environment-file copies and packages browser assets. The original local environment is preserved. Browser security headers and no-store/no-referrer authentication responses are configured. A read-only readiness checker distinguishes configuration shape from real infrastructure verification. The unreconciled Render blueprint remains explicitly unreconciled.
- **Recurring verification:** `.github/workflows/security.yml` defines regression, database, type, lint, build, advisory and synthetic HTTP checks. It has not been pushed or run on hosted CI. Tests use a disposable database and no provider credentials. Independent database suites run serially, preserving each test's intentional request concurrency.
- **Scanner robustness:** full history was scanned without printing credential values. Unstaged deletions now scan their index bytes, preserving secret detection while allowing legitimate file removal; symlink-containment tests still pass.

These cannot be closed through the authorized local-only workflow:

1. **Production migration/configuration and provider ownership:** verify the intended deployment/database, baseline, backup and migration status; apply the six recorded migrations through an authorized release. Configure explicitly chosen platform-admin user IDs, strong separate session/cron secrets, correct HTTPS origin, verified Resend sender, actual Teams tenant/channel/account links, and intended AI/S3 settings. Exercise actual email, scheduler, Teams, AI and avatar workflows. No credentials or privileged user IDs were invented.
2. **Historical credential evidence:** A local development configuration file in the pre-cleanup history at commit `e84aa62c7ea5ce2a8f003e54833d7d56cf5859a1` contains a historical remote PostgreSQL credential-shaped URL. This confirms historical tracking, **not present validity or compromise**. Obtain rotation/revocation evidence from the database operator. Do not test that credential or rewrite history without separate authorization. Docker/template matches were classified separately. The current process and inspected shell startup files contain no TLS-verification bypass; no host settings were changed.
3. **Destructive retention cleanup:** new writes are minimized and newly requested conversation deletion erases content. Existing excerpts, deleted-conversation messages and old unbound caches may remain in an existing database/backups. Review the inventory and approve the exact target/retention policy before using [retention-cleanup.sql](security/retention-cleanup.sql). Its destructive statements are commented out and were not executed. Provider retention and backups require separate confirmation.
4. **Infrastructure and incident evidence:** verify HTTPS/proxy trust, database network and least-privilege access, S3 IAM/bucket policy, backups, provider budgets and host resource limits. Parser workers are separate processes with sampled memory enforcement, not a hard operating-system sandbox or host-global resource quota. Memory may briefly exceed its threshold between samples. Failed/pending digest claims deliberately require operator reconciliation before retry, since provider delivery may be ambiguous.
5. **Unobserved behavior:** no production request/audit/cloud/provider logs were accessed. Original startup-log inspection was too small to establish an incident timeline; synthetic test logs provide verification evidence only. No compromise is inferred from source vulnerabilities. Real Microsoft token validation and external end-to-end integrations, hosted CI, Linux Docker-image execution, and exhaustive browser/adversarial fuzz coverage remain unverified.
