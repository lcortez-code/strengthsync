The assessment confirmed an existing-account takeover chain and several authorization, confidentiality, output-handling, and resource-control defects. The consolidated scan records **23 source-confirmed findings: 1 critical, 4 high, 17 medium, and 1 low**, grouped by related behavior below. Confidence in the source defects is high; specific exploit/deployment limitations are stated alongside each issue. The changes described below are implemented in the local working tree and covered by targeted regression tests. They are not deployed, committed, or production-verified. Remaining dependency advisories and operational checks are recorded separately.

Scope covered the current working tree, including uncommitted work: authentication and account administration; organization and role boundaries; profiles, cards, AI context and chat; feed, recognition, mentorship and reviews; exports and uploads; email and Teams integrations; configuration, dependency manifests, and secret-handling controls. Review combined source tracing, independent review of sensitive paths, actual TypeScript handler/helper tests with mocked service boundaries, and disposable local PostgreSQL/HTTP validation. It was not an exhaustive proof of every route, dependency, or deployment control.

Pre-existing changes to `.beads/interactions.jsonl`, `AGENTS.md`, and the untracked `start-app`, `stop-app`, and `restart-app` scripts were preserved. The startup helper was additionally restricted to loopback listening. No reset of the working tree, commit, push, deployment, production mutation, or external provider test was performed.

## Architecture and trust boundaries

StrengthSync uses a Next.js App Router UI and API backed by Prisma/PostgreSQL. A global `User` holds credentials and account data; an `OrganizationMember` holds tenant membership, status, and OWNER/ADMIN/MANAGER/MEMBER authority. Public registration can create a new organization and its OWNER, so tenant administration is an attacker-accessible role. It must not grant control over another user's global credentials or platform-wide data.

Authentication uses credentials and seven-day encrypted JWT sessions. The updated callback rereads the credential binding and active membership, derives the role from the database, and validates requested organization switches. Password changes invalidate old sessions; removed or inactive membership invalidates the organization session. APIs enforce their own authorization because middleware excludes API paths. See `src/lib/auth/config.ts:67` and `src/middleware.ts:118`.

| Resource / boundary | Effective consumer and recipient | Enforcement and limits |
| --- | --- | --- |
| Global identity → organization membership | Sign-in, account settings, invitation acceptance, member administration | Existing users receive a PENDING invitation bound to user, organization, role and membership version. Only that signed-in user can accept it once. Admin resets send a link to the account owner; they do not return a replacement password. New-account onboarding still uses generated temporary credentials. `src/app/api/organizations/invitations/route.ts:8`; `src/app/api/admin/members/route.ts:182`. |
| Browser/API → PostgreSQL | Account data, tenant records, rankings, social content, reviews, AI conversations and usage | Structured Prisma predicates and scoped conditional writes; application authorization is the observed tenant boundary. Database row-level security and production database privileges were not established. `src/lib/prisma.ts:1`. |
| Member data → peer/UI/model | Names, profile details, uploaded strengths and personalized insights | Full profiles are available to self and same-tenant MANAGER/ADMIN/OWNER; peers receive the permitted basic/top-five view. Both tenant and ACTIVE status checks are necessary in addition to role checks. `src/lib/auth/permissions.ts:29`; `src/lib/ai/context/user-context.ts:82`. |
| Upload → parser/storage | PDF strengths reports, administrator spreadsheets, avatar images | Bounded multipart reads; PDF 10 MB/100-page limits; extracted PDF data is persisted in PostgreSQL. Avatar objects use generated `avatars/` keys in the configured S3 bucket. Original PDF object persistence is not implemented by the inspected handler. `src/lib/api/upload.ts:6`; `src/lib/pdf/parser.ts:507`; `prisma/schema.prisma:226`; `src/lib/storage/index.ts:122`. |
| Application → OpenAI | Selected model receives authorized prompt/context; PostgreSQL stores usage and prompt/response excerpts | Provider is optional, with database-backed admission before generation. Chat accepts bounded text and disables remote asset downloads. Prompt instructions are not authorization controls; no model tools are bound in the inspected chat invocation. `src/lib/ai/client.ts:4`; `src/lib/ai/rate-limiter.ts:58`; `src/app/api/ai/chat/route.ts:191`. |
| Scheduler/admin → email recipients | Resend receives account emails and weekly digests; preview is browser-visible HTML | Global dispatch requires a nonempty header cron secret. Manual dispatch is tenant-scoped, and test mode requires the current authenticated user and organization. HTML is escaped and preview responses use a sandbox policy. `src/app/api/email/digest/route.ts:73`; `src/app/api/email/digest/route.ts:131`. |
| Application → Teams | Organization-configured Microsoft webhook or explicitly organization-bound environment fallback; Bot Framework entry point separately uses CloudAdapter | HTTPS Microsoft destination allowlist, no redirects, timeout, and private-shoutout filtering. Bot authentication is delegated to CloudAdapter; account-linking/multi-membership behavior needs separate deployment validation. `src/lib/integrations/teams-url.ts:2`; `src/lib/integrations/teams-webhook.ts:84`; `src/app/api/integrations/teams-bot/route.ts:130`. |
| Tenant admin → shared platform resources | Global strength constants and AI prompt templates | Operator-managed immutable user-ID allowlist, separate from organization roles. Prompt-template writes were reachable before the fix, but no current product route calling `generateFromTemplate` was found; active prompt poisoning through those templates was not established. `src/lib/auth/platform-admin.ts:3`. |

Primary assets are global credentials and reset authority; tenant membership and roles; personal strengths and review information; private social content; provider credentials/webhook destinations; AI and email spending; and audit/usage records. Threat actors considered include anonymous callers, self-registered tenant owners, ordinary members, demoted or removed members, and actors supplying stored text, identifiers, URLs, or uploaded documents. Provider, database, host and operator controls are assumptions unless verified below.

Deployment manifests describe intended deployment, not observed infrastructure. In particular, `render.yaml:2` labels its configuration unreconciled/inferred. The Dockerfile expects standalone Next.js output while `next.config.ts:7` leaves it disabled. Neither manifest establishes current production networking, secrets, backups, or deployment state.

## Deployment prerequisites and remaining work

These are prerequisites for a future authorized release; this assessment did not perform that release.

1. Apply `prisma/migrations/20260915000000_ai_usage_reservations/migration.sql` to the verified intended database using the normal migration workflow, then generate the matching Prisma client. It adds `AIUsageLog.reservedTokens` and `settledAt`; legacy totals remain valid. It has been applied only to the disposable test database. Deploy compatible schema before the new application code; admission fails closed if the database cannot support it.
2. Configure a strong `NEXTAUTH_SECRET` and the correct public HTTPS `NEXTAUTH_URL`. The credential-binding change requires existing sessions to sign in again. Old outstanding plaintext-stored reset links require reissuance through the new hashed-token flow.
3. Configure `RESEND_API_KEY` and a verified `RESEND_FROM_EMAIL` for invitations and password reset. Validate sender ownership and actual delivery in an authorized environment. With no email configuration, existing-account invitation/reset fails closed. `NEXTAUTH_URL` must resolve to the intended recipient-facing application.
4. Set `STRENGTHSYNC_PLATFORM_ADMIN_USER_IDS` to explicitly selected existing immutable user IDs for platform operators. With no allowlist, tenant owners cannot administer global constants/templates.
5. Configure a nonempty `CRON_SECRET`. The digest sender accepts bearer or `x-cron-secret` headers; query-string secrets are no longer supported. Ensure the scheduler uses the sending POST endpoint. The committed `vercel.json` schedule targets the digest path, but schedule declaration alone does not prove authenticated POST delivery.
6. For Teams, use a supported Microsoft HTTPS webhook. If using `TEAMS_WEBHOOK_URL`, also set `TEAMS_WEBHOOK_ORGANIZATION_ID`; fallback is unavailable to other organizations. Clearing a per-organization setting does not clear this operator fallback. Verify intended channel ownership and bot account linking before enabling production delivery.
7. For AI, configure `OPENAI_API_KEY` and optional `OPENAI_ORG_ID` only in the intended environment; confirm provider retention/spending controls independently. Unknown or interrupted requests conservatively consume reserved daily allowance. Usage summaries record reported usage; retained allowance is a quota safeguard, not a provider invoice.
8. For avatars, configure `AWS_REGION`, `AWS_S3_BUCKET`, `AWS_ACCESS_KEY_ID`, and `AWS_SECRET_ACCESS_KEY`; verify bucket policy/IAM, object access and retention. Image optimization now restricts remote images to the configured bucket's avatar prefix. Existing externally hosted avatars need compatibility review. Do not infer bucket privacy from the code.
9. Reconcile the actual hosting configuration, HTTPS/proxy settings, database network restrictions/backups, standalone Docker output and environment separation before release. Apply dependency follow-up through a compatibility-tested change.

Coverage gaps remain: production traffic and incident forensics; full Git-history secrets; live email, OpenAI, S3 and Teams behavior; cloud IAM/network controls; comprehensive browser and parser adversarial testing; and exhaustive per-route review. No confirmed SQL/shell injection or forged Bot Framework authentication chain was found in the inspected paths, which is narrower than proving their absence. Login/registration abuse controls and external rate limiting were not established; reset issuance cooldown does not provide general login protection. Synchronous document parsing remains in-process despite bounds. The Teams account-mapping creation flow and multi-membership organization selection need a dedicated review before relying on the integration.
